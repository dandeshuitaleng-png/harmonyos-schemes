# 织日 / WovenDay

## 产品目标

为用户留住少量“值得继续穿”的衣物：记录它的个人称呼、当下状态、用户自定的养护约定，以及送修/清洁前可自行分享的说明摘要。核心体验是把一件衣物从“先放着”变成一个可完成的小行动。

## MVP：两周内只完成这条路径

1. 新建衣物卡：自定义名称、类别、可选照片、状态文字和下一步日期。
2. 添加用户自己的“照看约定”和一次事件（例如清洁、缝补、送修或收回）；应用不解释方法是否正确。
3. 在卡片详情生成只读“交接单”：衣物名、用户勾选的说明、需要确认的事项和可选联系称呼；用户审阅后走系统分享。
4. 首页显示下一件待处理衣物；若服务卡片可用，只展示名称、日期和进入详情的动作。

## 技术架构与目录

- 使用 ArkTS、ArkUI 与本地持久化；业务数据模型至少包括 `Garment`、`CareNote`、`CareEvent`、`ShareDraft`。
- 建议目录：`entry/src/main/ets/pages/`（列表、编辑、详情、预览），`features/garment/`（状态与用例），`data/local/`（持久化），`components/`（无障碍可复用组件），`entryformability/`（仅在实现卡片时加入）。
- 照片、收据或服务单只能经系统 Picker 临时选择；附件不能成为保存一张衣物卡的前提。分享只传用户确认的文本摘要，默认不附图、不附原始文件。
- 不接后端、不建立账号、不采集位置、不抓取商品或品牌数据库。离线即是 MVP 的正常模式。

## 原生交互

- 首页是“待照看”而非仪表盘：一张主卡、少量近期事件和明确的新建入口；空态提供“记录第一件衣物”。
- 长按衣物卡可归档或删除，删除前说明将移除本地记录；卡片操作必须可由读屏完成。
- 日期可为空；若用户拒绝通知或卡片不可用，仍在应用内以文字显示下一步日期，绝不假装已提醒。
- 150% 字号、深色模式、高对比下，状态、日期和主要操作不能被截断；所有无文字图标都提供可读标签与后果说明。

## 数据、隐私与失败状态

- 默认本地保存。照片、备注、联系人称呼、收据可能是敏感个人信息；编辑页解释其仅存在本机，除非用户主动分享。
- Picker 取消、照片不可读、空间不足、分享取消、通知关闭、无附件、无网络都要有明确提示且可继续保存核心文字记录。
- 分享预览必须逐项可移除；联系人只写用户输入的称呼，不写电话、地址或第三方身份信息。

## 验收标准

- 飞行模式下可新建、编辑、归档、删除一件衣物，并在重启后保留。
- 无照片、无通知权限、Picker 取消时，用户仍能完成“新建—记录事件—生成交接摘要”的主路径。
- 分享前能看见完整内容并取消；取消后原记录保持不变。
- 读屏与 150% 字号下完成上述路径；每个图标操作均有可理解的无障碍名称。

## 禁止事项

- 不做穿搭推荐、衣橱全量盘点、商品比价、二手交易、服务商撮合、AI 鉴定或品牌/面料数据库。
- 不提供洗涤、去渍、修补、化学品或过敏安全建议，不将用户备注包装为专业结论。
- 不复制竞品的商品图片、服装数据、商标、评分、服务商信息或界面文案；不声称“鸿蒙没有同类”。
