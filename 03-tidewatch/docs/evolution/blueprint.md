# Blueprint B1 · TideWatch v0.2.0

2026-09-22冻结本轮基线。产品身份沿用assessment；原完整路线见../workflow/development-plan.md，当前冲突以本文件的明确版本范围为准。

## 原则

- P-001 本机优先：同意保存后无账号/无网络仍可创建、重启读取；网络功能与账号不在本轮。
- P-002 数据不静默丢失：迁移须先校验，事务内完整写入，再验证与清理旧副本；异常暂停修改。删除后不能因旧缓存“复活”。
- P-003 状态真实：不把本地保存称为上传/审核，不推断缺失的观察分类。
- P-004 最小权限：本轮不新增权限、依赖、真实位置或联网服务；隐私选择继续独立存储。

## 架构与实现

A-001：沿用Observation.ts与ObservationRepository的SnapshotIO契约；新增RdbSnapshotIO.ets将结构化字段分别存入observations表，meta保存schema版本/初始化完成状态。采用@kit.ArkData relationalStore，无额外包，安全等级S2，应用私有目录。继续200条上限；不宣称已优化全量列表性能。
替代：继续Preferences最小改动，但不提供事务；单行JSON数据库不利于后续附件关联。选择规范化记录表，暂保留SnapshotIO编码适配以降低界面/领域回归风险。

A-002：首次读取才迁移；只有用户同意后的load打开数据库。事务中建表、检查meta；若meta无版本且records已存在则失败，不覆盖未知库。旧草稿使用现有decodeRecords严格校验后批量写入，版本与迁移标记同事务提交。迁移期在meta暂存migration_expected用于跨进程中断后的读回比对，只有旧副本清理完成后才删除该暂存值；提交后从库读回并验证；之后删除Preferences drafts键并flush，隐私选择不变。清理失败不授予修改能力，下次读取重试；每次load均执行清理，防止失败的Preferences缓存遮掩磁盘残留。后续读取以数据库为准，不把空记录库当成未初始化。
原始偏好值在事务提交前保持不变，充当迁移回退来源；验证成功后不长期保留隐藏个人数据副本。已迁移版本不支持直接降级到只读Preferences的旧应用；回退代码前需通过新版本导出/修复流程恢复数据，不自动删库或自动回滚。

A-003：新建/编辑/删除沿用完整字段校验→写入互斥→事务替换集合→提交→UI更新。异步操作在一个原生Transaction对象上执行，出错rollback并传播；未知数据库版本/损坏内容不回退为空。SELECT固定列且绑定输入参数，关闭ResultSet。排序通过position保持旧集合顺序与ID，不重建ID或刷新有效期。未来附件需逐条更新/关联表，不在本轮引入假附件。

A-004：领域规则用Node测试；SQL契约做真实SQLite语义测试（非HarmonyOS替代）；另建临时设备测试工程，以独立测试bundle调用生产RdbSnapshotIO在真实HarmonyOS关系型存储中测试迁移、事务失败和重开恢复。注入数据库触发器造成写入失败验证rollback，禁止以mock冒充原生集成。测试入口不进入生产HAP。

目录依赖：Index → ObservationStore（隐私与backend装配）→ ObservationRepository（门禁）→ SnapshotIO/RdbSnapshotIO → relationalStore。SQL常量与行映射放ObservationSchema.ts，仅依赖Observation。状态：界面拥有busy/ready及表单，repository拥有写门禁，数据库meta拥有迁移状态。

## 用户流程与失败

同意隐私→加载或首次迁移→读取原记录→原有新建/编辑/删除→提交后反馈→重启读取。升级自动进行，不要求用户手动复制数据。加载文案允许表达“正在准备本机记录”；不向用户展示SQL/数据库版本等内部细节。失败沿用“保护原记录/重试读取”，不提供一键破坏性重置。
UI契约见ui-spec.md。业务字段不变，不新增权限；隐私说明补充升级迁移后旧草稿副本清理的行为。

## 验收

- AC-001：当前工作树17项基线测试/完整构建通过，IDE独立窗口存在；记录基线哈希。
- AC-002：空库首次打开、保存两条含中文/引号记录、关闭并重开后字段/顺序一致；原生设备证据必须通过。
- AC-003：旧JSON及旧分隔格式迁移后ID/采集/截止保持，含过期记录；提交前旧数据未清理，成功后旧草稿键消失，隐私选择保留；原生设备测试。
- AC-004：数据库触发器阻断插入时，替换事务回滚保留原集合；移除触发器并reload后可重试；原生测试＋仓储回归。
- AC-005：无效旧数据、未知库版本、记录损坏拒绝覆盖；迁移成功后清空/重开不复活；原生测试。
- AC-006：生产UI创建/编辑/删除与强停恢复、隐私拒绝隐藏/再次同意恢复；浅/深色截图，表单返回确认；原生UI操作。
- AC-007：当前源码清单、测试/构建/设备报告、干净复制构建、仓库守卫及使用说明一致；新代码未把测试入口带入生产路由。
