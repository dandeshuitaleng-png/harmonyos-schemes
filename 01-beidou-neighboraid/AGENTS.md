# 北斗邻援 / Beidou NeighborAid

## 任务

设计面向社区、景区与乡镇的离线优先应急互助应用：在弱网或断网时记录 SOS、避险点、道路障碍和物资点，并在设备重新联网后提交经人工审核的摘要。

## 灵感与改造

- 研究来源：[OpenRescue](https://github.com/Anbu-00001/Offline-First-Emergency-Coordination-System) 的离线地图、P2P 与 CRDT 思路。
- 改造重点：不复刻其代码或品牌；聚焦国内社区演练、北斗定位可用时的坐标增强、家庭预案与一次性事件包。
- 同类核验：公开资料未发现该功能组合的鸿蒙直接同类；立项前复核应用市场和 OpenHarmony 社区。

## MVP

1. 下载一块离线地图和演练包；创建本地 SOS/风险/资源卡。
2. 通过系统允许的近场能力交换加密事件摘要；冲突保留来源与时间，不自动覆盖。
3. 网络恢复后仅由用户确认上传；审核端显示待核验事件。

## 鸿蒙实施

- ArkTS/ArkUI 原生；地图数据离线分区存储，定位权限按需申请。
- 服务卡片只显示用户已订阅地区的预警与“演练模式”；元服务不得承担断网救援核心流程。
- 评估分布式数据/近场通信的真实 API 能力后再写入承诺；不可假定任意手机均可组成 mesh。

## 数据与安全

- 默认本地保存；SOS 联系人与精确坐标均须单独同意。
- 不把应用称为官方报警或替代 110/119/120；紧急页始终提供系统电话入口。
- 事件必须含时间、精度、来源和审核状态；AI 只能协助归类，不可判定救援优先级。

## 验收

- 飞行模式下仍可查看已下载地图、创建与导出事件。
- 两份冲突事件可追溯而不丢失；上传前可预览字段。
- 读屏、字号放大和高对比下可独立完成 SOS 演练。
