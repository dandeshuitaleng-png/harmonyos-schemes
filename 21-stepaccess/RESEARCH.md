# 步道通研究记录（2026-08-30）

## 通过原因

本候选以“单段步道的个人辅助器具体验记录”为最小边界；它区别于现有的自然观察、灾害收集、预约和学习方案，不要求一开始获得地图、政府、支付或身份服务。

## 可复核来源

1. [StreetComplete](https://github.com/streetcomplete/StreetComplete)：项目说明其以简单问题帮助非 OSM 专业用户现场补充地图信息、支持离线调查；仓库为 GPL-3.0，因此本项目不复用其代码、题库或 UI。
2. [Project Sidewalk](https://github.com/ProjectSidewalk/SidewalkWebpage)：项目说明其记录路缘坡、障碍、路面问题和缺失人行道，并公开标准数据格式；本项目只借鉴数据分级和观察维度。
3. [AccessVis](https://github.com/ProjectSidewalk/accessvis)：展示步道无障碍数据如何按区域及障碍因素进行可视化；它不是本项目的代码或地图依赖。

## 淘汰记录

- 数字身份钱包：需要可信凭证发行方、合规主体和安全审计，风险项未达线。
- 食品条码与冰箱库存：与现有 `16-fridge-pantry` 的问题域重叠。
- 通用离线地图：与既有灾害与观察地图方案重叠，且地图数据/导航责任过重。
- 全量城市无障碍评分：没有审核组织和数据来源，不满足“可验证 MVP”门槛。

## 待核验

- 目标地区的社区合作方及其审核/撤回机制。
- 目标系统版本下相机、定位、地图组件、服务卡片和本地数据库 API 的可用性。
- 应用市场、元服务中心和 OpenHarmony/Gitee 的人工同类检索留档。
